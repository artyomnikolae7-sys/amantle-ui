# 3-Минутный Конвейер Обновления, Копирования и A/B Тестирования Компонентов

## Постановка проблемы

Сейчас добавление нового компонента или перенос компонента из открытых shadcn-библиотек (Magic UI, 21st.dev, Cult UI, Aceternity, ReUI) в AMANTLE UI требует множества ручных шагов:
1. Ручной анализ пропсов и зависимостей компонента.
2. Ручная замена хардкод-классов Tailwind на CSS-токены дизайн-системы.
3. Ручное создание превью-обёртки в `lib/components-map.tsx`.
4. Ручное написание схемы Playground в `lib/playground-schemas.ts`.
5. Ручной запуск сборки реестра и проверка превью на ошибки.
6. Отсутствие механизма A/B сравнения — невозможно визуально сравнить оригинальный референс с адаптированной версией AMANTLE UI.

Из-за этого перенос одного компонента занимает 15–20 минут. Наша цель — **сократить этот цикл до ~3 минут на компонент** с полным сохранением качества, валидацией типов, тестами и A/B-сравнением.

## Решение

Создание сквозного автоматизированного конвейера (Pipeline CLI + Showcase A/B Engine):
1. **Анализ (`pipeline analyze`)**: парсит исходник компонента, извлекает пропсы, типы, зависимости и хардкодные токены.
2. **Скрины и Визуальный снепшот (`pipeline snapshot`)**: генерирует визуальное превью и фиксирует эталонное состояние.
3. **Реализация (`pipeline adapt`)**: трансформирует стили под Tailwind v4 CSS Variables, проставляет `source provenance` JSDoc, сохраняет компонент в `registry/`.
4. **Тесты (`pipeline test`)**: валидирует TSX, запускает `buildRegistry()`, проверяет доступность роута `/preview/<category>/<name>`.
5. **А/Б реализация и Сравнение (`Showcase A/B Compare`)**: добавляет интерактивный режим A/B сравнения в `ShowcaseViewer`:
   - Сравнение Варианта A (Оригинал / Исходный референс) и Варианта B (AMANTLE UI адаптация).
   - Сплит-просмотр, дифф токенов и стилей.
6. **Добавление на сайт (`pipeline publish`)**: автоматически прописывает демо в `lib/components-map.tsx` и генерирует контролы для таба `Playground` в `lib/playground-schemas.ts`.

## Критерии приёмки (К1 – К8)

- **К1**: Создан скрипт оркестратора `scripts/pipeline.mjs` (команда `npm run pipeline`), выполняющий шаги Анализ → Адаптация → Регистрация → Сборка → Тесты за один вызов.
- **К2**: Модуль анализа автоматически парсит пропсы (варианты, размеры, boolean-флаги, текст), зависимости (lucide, radix, motion) и хардкодные классы цвета/отступов.
- **К3**: Модуль адаптации автоматически генерирует чистый TSX-код с CSS-токенами AMANTLE UI (`bg-primary`, `text-muted-foreground`, `border-border`, `--radius`) и сохраняет JSDoc provenance (`@source`, `@author`, `@license`, `@modified`).
- **К4**: Модуль автоматической регистрации добавляет компонент в `lib/components-map.tsx` и автоматически генерирует схему контролов для вкладки Playground в `lib/playground-schemas.ts`.
- **К5**: В `ShowcaseViewer` добавлен режим A/B-сравнения (`[⚖️ A/B Compare]`): визуальное side-by-side сравнение Варианта A (исходный референс) и Варианта B (AMANTLE UI адаптация), а также дифф токенов.
- **К6**: Модуль тестирования проверяет компиляцию, сборку манифеста в `public/r/*.json` и возвращает статус валидации роута превью.
- **К7**: Полный цикл адаптации одного компонента через `npm run pipeline` занимает менее 10 секунд машинного времени, позволяя завершить весь процесс (анализ, адаптация, визуальный контроль) за ~3 минуты.
- **К8**: Проведена демонстрация работы пайплайна на новом компоненте: компонент успешно проанализирован, адаптирован, протестирован, зарегистрирован и отображается на сайте с A/B-сравнением.
