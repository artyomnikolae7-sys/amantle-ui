# AMANTLE UI DESIGN SYSTEM — Релиз v1 (Registry & Showcase)

## Постановка проблемы

Разработчики и продуктовые команды сталкиваются с ограничениями традиционных UI-библиотек (npm-монолитов):
1. **Vendor Lock-in и потеря контроля**: Невозможно тонко кастомизировать дизайн, анимации и логику стороннего пакета без костылей и форков.
2. **Сложность внедрения в AI-экосистему**: Современные инструменты разработки (Cursor, Claude Code, Antigravity) тратят много токенов и генерируют неконсистентный UI, если у них нет прямого доступа к структурированному реестру и токенам проекта.
3. **Разрозненность решений**: Качественные компоненты, блоки и шаблоны раскиданы по десяткам разных репозиториев без единой стандартизированной системы стилей и проверки юридической чистоты (лицензий).

## Решение

Создание **AMANTLE UI (v1)** — независимой платформы-экосистемы компонентов уровня shadcn/ui:
- **Полное владение кодом (Code Ownership)**: Разработчик копирует чистый, высококачественный исходный код прямо в проект через CLI (`npx shadcn add`) или через буфер обмена.
- **Интерактивная витрина (Showcase)**: Каталог с живым превью компонентов в изолированном Iframe-песочнице с поддержкой мобильных, планшетных и десктопных вьюпортов, а также динамическим переключением светлой/тёмной темы и цветовых палитр.
- **Встроенный MCP-сервер для AI**: Нативная интеграция для AI-ассистентов через Model Context Protocol с инструментами поиска компонентов, извлечения исходного кода и получения токенов тем.
- **Юридическая прозрачность (Provenance)**: Каждый компонент несёт строгую атрибуцию источника, автора и совместимой open-source лицензии (MIT/Apache 2.0).

## Как выглядит готовое

### Сквозной сценарий разработчика (Web & CLI)
1. **Точка входа**: Разработчик открывает главную страницу витрины AMANTLE UI.
2. **Обзор каталога**: Видит шапку с глобальным поиском, переключатель темы (Dark/Light + палитры: Zinc, Slate, Violet, Emerald, Rose) и счётчик компонентов «Золотого фонда» (50+ элементов).
3. **Навигация**: Переключается между вкладками `UI Components` (примитивы), `Blocks` (готовые секции страниц) и `Templates` (полноценные шаблоны).
4. **Просмотр компонента**: Переходит в карточку компонента (например, `Button` или `Pricing Table`):
   - Видит изолированное окно превью (Iframe Viewport), может переключать размеры экрана: Mobile (375px), Tablet (768px), Desktop (100%).
   - Тестирует интерактивные состояния: hover, focus, disabled, переключение пропсов/вариантов.
   - Видит вкладку с кодом (чистый TypeScript/Tailwind TSX с подсветкой синтаксиса).
   - В один клик копирует CLI-команду (`npx shadcn add https://amantle.dev/r/button.json`) или исходный код.
   - Видит блок Provenance с оригинальной ссылкой на репозиторий и лицензией MIT.

### Сквозной сценарий AI-ассистента (MCP)
1. AI-агент в IDE пользователя обращается к MCP-серверу AMANTLE UI.
2. Вызывает `search_registry("pricing with toggle")` и мгновенно получает список соответствующих блоков.
3. Вызывает `get_component("pricing-block")` и получает JSON с чистым TSX-кодом и списком необходимых npm-зависимостей.
4. Вызывает `get_theme_tokens("violet-dark")` и получает CSS-переменные для глобальной конфигурации проекта.

## Критерии приёмки

- **К1**: Проект запускается локально командой `npm run dev` на Next.js 15+ App Router, отображая главную страницу каталога без ошибок в консоли.
- **К2**: В каталоге представлены 3 раздела (`ui`, `blocks`, `templates`), общее число курируемых компонентов «Золотого фонда» составляет не менее 50 единиц с полной TypeScript-типизацией.
- **К3**: На странице каждого компонента работает изолированное превью (iframe sandbox) с переключением трёх режимов вьюпорта (Mobile 375px, Tablet 768px, Desktop 100%).
- **К4**: В каталоге и в превью компонентов работает глобальный переключатель темы: Dark / Light режим и переключение минимум 5 цветовых тем (Zinc, Slate, Violet, Emerald, Rose).
- **К5**: У каждого компонента есть кнопка «Copy CLI command» (в формате `npx shadcn add <url>`) и кнопка «Copy Code», копирующая чистый TSX-код в буфер обмена.
- **К6**: Каждый файл компонента содержит JSDoc-шапку с полями `@source`, `@author`, `@license`, `@modified`.
- **К7**: Команда `npm run build:registry` валидирует все компоненты и генерирует статические JSON-артефакты в каталоге `public/r/` (`index.json` и файлы `public/r/[name].json`), строго совместимые со схемой `shadcn/ui registry v2`.
- **К8**: Запрос `GET /r/button.json` возвращает валидный JSON shadcn-реестра с полями `name`, `type`, `dependencies`, `registryDependencies`, `files`.
- **К9**: Встроенный MCP-сервер AMANTLE UI успешно запускается и регистрирует 4 инструмента: `search_registry`, `get_component`, `list_categories`, `get_theme_tokens`.
- **К10**: Вызов MCP-инструмента `search_registry` с произвольным поисковым запросом возвращает отфильтрованный список компонентов с тегами и описаниями.
- **К11**: Вызов MCP-инструмента `get_component` возвращает полный код компонента, список зависимостей npm и зависимостей реестра.
- **К12**: Вызов MCP-инструмента `get_theme_tokens` возвращает валидный блок CSS-переменных для `globals.css`.

## Пользовательские истории

1. Как frontend-разработчик, я хочу скопировать команду `npx shadcn add` со страницы компонента, чтобы мгновенно внедрить компонент в свой Next.js проект без ручной настройки стилей.
2. Как разработчик, я хочу протестировать компонент на экранах 375px, 768px и Desktop прямо на витрине, чтобы убедиться в его корректной адаптивности до установки.
3. Как дизайнер-разработчик, я хочу переключать тему оформления (светлая/тёмная и цветовые палитры) на витрине, чтобы оценить, как блоки выглядят в разных стилях.
4. Как разработчик, я хочу скопировать чистый TSX-код компонента одним кликом, чтобы быстро использовать его в проекте без использования CLI.
5. Как тимлид, я хочу видеть в каждом компоненте карточку Provenance и лицензию (MIT), чтобы исключить риски нарушения авторских прав в корпоративном коде.
6. Как разработчик, использующий Cursor / Claude Code / Antigravity, я хочу подключить MCP-сервер AMANTLE, чтобы AI-ассистент сам подбирал и внедрял нужные компоненты прямо во время диалога.
7. Как AI-агент, я хочу вызвать `search_registry`, чтобы найти наиболее подходящие блоки под текстовый запрос пользователя (например, «форма логина с двухфакторной аутентификацией»).
8. Как AI-агент, я хочу вызвать `get_theme_tokens`, чтобы получить точные CSS-токены темы и единообразно стилизовать весь проект пользователя.
9. Как мейнтейнер проекта, я хочу запускать `npm run build:registry`, чтобы все изменения в папке `registry/` автоматически компилировались в валидные статические JSON-манифесты в `public/r/`.
10. Как контрибьютор, я хочу добавлять новый компонент в папку `registry/ui/`, чтобы сборщик автоматически распознавал его зависимости и включал в общий каталог.

## Решения по реализации

### Архитектура каталогов
```
├── app/
│   ├── (marketing)/
│   │   ├── page.tsx               ← Главная страница витрины и поиск
│   │   ├── components/            ← Каталог компонентов с фильтрами
│   │   └── [category]/[slug]/     ← Детальная страница компонента с превью
│   ├── preview/[category]/[slug]/ ← Изолированный роут для рендеринга в iframe
│   └── api/
│       └── mcp/route.ts           ← MCP Server SSE / HTTP эндпоинт
├── components/                    ← Внутренние UI-компоненты сайта витрины
├── registry/                      ← Исходники компонентов «Золотого фонда»
│   ├── ui/                        ← Примитивы (Button, Dialog, Tabs, etc.)
│   ├── blocks/                    ← Секции (Hero, Pricing, Bento, etc.)
│   ├── templates/                 ← Шаблоны страниц (Landing, Dashboard)
│   ├── hooks/                     ← Кастомные хуки (use-media-query, etc.)
│   └── lib/                       ← Общие утилиты (utils.ts)
├── scripts/
│   └── build-registry.ts          ← Сборщик реестра в public/r/
├── lib/
│   ├── mcp/                       ← Реализация инструментов MCP-сервера
│   └── registry.ts                ← Чтение и типизация реестра
└── public/
    └── r/                         ← Скомпилированные JSON реестра
```

### Состав «Золотого фонда» (v1: 50+ компонентов)
1. **Примитивы `ui/` (~25 шт.)**: `button`, `input`, `textarea`, `select`, `dialog`, `sheet`, `dropdown-menu`, `popover`, `tooltip`, `tabs`, `accordion`, `avatar`, `badge`, `card`, `checkbox`, `radio-group`, `switch`, `slider`, `table`, `separator`, `skeleton`, `alert`, `sonner`, `progress`, `toggle`.
2. **Секции `blocks/` (~20 шт.)**: 
   - Hero: `hero-simple`, `hero-gradient-glow`, `hero-badge-cta`
   - Pricing: `pricing-cards-tier`, `pricing-comparison-table`
   - Bento & Features: `bento-grid-3x3`, `feature-cards-grid`, `feature-alternating-rows`
   - Social Proof: `testimonials-slider`, `stats-counter-strip`, `faq-accordion`
   - Navigation & Footers: `navbar-sticky-blur`, `footer-mega-columns`
   - Dashboard blocks: `dashboard-stats-kpi`, `dashboard-recent-transactions`
3. **Шаблоны `templates/` (~3 шт.)**: `saas-landing-page`, `modern-dashboard-page`, `auth-split-screen-page`.

### MCP Server Toolset
1. `search_registry`: входные параметры `{ query: string, category?: string }`. Возвращает список компонентов с метаданными.
2. `get_component`: входные параметры `{ name: string }`. Возвращает `{ name, code, dependencies, registryDependencies }`.
3. `list_categories`: возвращает дерево категорий и количество компонентов.
4. `get_theme_tokens`: входные параметры `{ theme: string, mode: "dark" | "light" }`. Возвращает CSS-переменные для `@theme` и `:root`.

### Новые зависимости
- `next@15`, `react@19`, `react-dom@19`, `typescript`
- `tailwindcss@4`, `@tailwindcss/postcss`, `postcss`
- `class-variance-authority`, `clsx`, `tailwind-merge`
- `@radix-ui/react-*` (полный набор доступных примитивов Radix)
- `lucide-react`
- `@modelcontextprotocol/sdk` (официальный SDK для MCP-сервера)
- `zod` (валидация схемы registry и параметров MCP)
- `sonner` (тосты)
- `shiki` (подсветка синтаксиса кода на витрине)

## Решения по тестированию

- **Шов 1 (Реестр)**: Проверка соответствия всех сгенерированных JSON-файлов в `public/r/` схеме Zod `registryItemSchema`. Тест запускается в рамках `npm run build:registry`.
- **Шов 2 (MCP API)**: Unit-тесты для функций инструментов MCP (`search_registry`, `get_component`, `list_categories`, `get_theme_tokens`).
- **Шов 3 (Сборка и типизация)**: `npm run build` — Next.js production build + TypeScript typecheck (`tsc --noEmit`).

## Вне рамок (Отложено на v2)

- Автоматический crawler/парсер внешних сайтов (сначала стабилизируем курируемый фонд и формат реестра).
- Visual Composer (визуальный drag-and-drop конструктор страниц отложен до готовности всей базы блоков).
- Deep Design Genome (генератор мутаций стилей по скриншотам).
- Внешняя база данных PostgreSQL/SQLite (v1 полностью статичен и автономен в файловой системе репозитория).

## Прочие заметки

- Все исходники, скрипты сборки и сгенерированные файлы реестра хранятся в репозитории на Google Drive.
- Поддерживается совместимость со стандартным клиентом shadcn CLI: любой сторонний разработчик сможет выполнить `npx shadcn add <url-to-amantle-item>`.
